# Еталон RM-320: підписи трьох рутин тактування в XIP

Мета — знайти ті самі три рутини в інших апаратах OMAP2420 за їхнім кодом
(підписом), а не за адресою: адреси в кожній прошивці свої. Усі vaddr нижче —
для RM-320 (`out/roms/rm320.rom`), база XIP `0x80000000`, тож
`файловий_зсув = vaddr − 0x80000000`.

Дизасемблювати вікно: `node tools/disrom.js <rom> <vaddrHex> <lenHex>`
(objdump ARM, автоматично підставляє base). Регістр множника OMAP2420
`CM_CLKSEL1_PLL = 0xc6008540` присутній у КОЖНОМУ образі — це головний якір,
від нього шукати решту.

## 1. Функція-читач множника (біля пулу 0xc6008540)

RM-320: пул `0x800b16ec` містить слово `0xc6008540`. Функція `0x800b1544`
читає його й обчислює множник:

```
800b1544: e92d4010  stmdb sp!, {r4, lr}
800b1548: e59f0198  ldr r0, [pc, #408]   ; -> адреса регістра
800b154c: eb0001c3  bl 0x800b1c60        ; венір-читач (e51ff004 ldr pc,[pc,#-4])
800b1560: e59f0184  ldr r0, [pc, #388]   ; = 0x800b16ec (пул 0xc6008540)
800b1564: eb0001bd  bl 0x800b1c60
800b156c: e1a00300  mov r0, r0, lsl #6    ; вибірка бітів CLKSEL множника
800b1570: e1b00ea0  movs r0, r0, lsr #29
800b1574: 03a000c0  moveq r0, #192        ; 0xc0 = 192 (значення множника)
800b1580: 03a00082  moveq r0, #130        ; 0x82
800b1584: 13a00078  movne r0, #120        ; 0x78
```

Що шукати в іншому апараті: `ldr rX,[pc]` на пул зі словом `0xc6008540`, одразу
за ним `bl` на венір `e51ff004` (`ldr pc,[pc,#-4]`). Записати: vaddr пулу, vaddr
функції-читача, vaddr веніра.

## 2. SRAM relock-рутина (KRomSramRoutine)

RM-320: `0x800a7f6c`. Це та рутина, копію якої ядро тримає в SRAM і виконує на
простої; ми перевіряємо перше слово її копії проти ROM.

```
800a7f6c: e92d40fe  stmdb sp!, {r1,r2,r3,r4,r5,r6,r7, lr}  ; НЕТИПОВА маска {r1-r7,lr}
800a7f70: e59f1128  ldr r1, [pc, #296]
800a7f7c: ee073f9a  mcr 15, 0, r3, cr7, cr10, {4}          ; барʼєр запису буфера
800a7f80: e5914070  ldr r4, [r1, #112]
800a7f84: e3844048  orr r4, r4, #72       ; 0x48 - виставляє біти в регістрі
800a7f88: e5814070  str r4, [r1, #112]
```

Підпис для пошуку: пролог `e92d40fe` (push {r1-r7,lr}) РАЗОМ із наявним поблизу
`mcr p15, 0, rX, cr7, cr10, {4}` (`ee..3f9a`) — це поєднання майже унікальне.
Записати vaddr прологу як `iRomSramRoutine`.

## 3. DSP divider setter (KDspSetter)

RM-320: `0x800ac59c`. Валідує аргумент-дільник і ставить його.

```
800ac59c: e3510009  cmp r1, #9
800ac5a0: e92d4010  stmdb sp!, {r4, lr}
800ac5bc: e3510010  cmp r1, #16           ; 0x10
800ac5c0: 13510012  cmpne r1, #18         ; 0x12
800ac5c8: e3e00005  mvn r0, #5            ; повертає -6 (KErrArgument)
800ac5cc: e8bd8010  ldmia sp!, {r4, pc}
```

Підпис для пошуку: `cmp r1,#9` впритул перед `stmdb {r4,lr}`, далі ланцюжок
`cmp/cmpne r1` проти значень 9,16,18 і `mvn r0,#5`. Записати vaddr `cmp r1,#9`
як `iDspSetter`.

## Формат звіту (`out/analysis/<dev>.md`)

Для кожного пункту: знайдений vaddr + 6–10 рядків дизасемблу як доказ. Якщо
підпис не знайдено — так і написати «не знайдено», не вгадувати. Пул множника
`0xc6008540` уже підтверджено в кожному образі (див. `findings.md` §30), його
vaddr узяти звідти як стартову точку.
