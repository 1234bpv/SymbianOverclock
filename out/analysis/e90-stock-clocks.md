# Незалежний аналіз XIP Nokia E90: перевірка адрес і штатна розкладка тактування

- **Файл ROM:** `out/roms/e90.rom` (розмір 1 769 472 байтів = 0x1B0000, нестиснутий XIP `SOS+UPDAPP`)
- **База завантаження:** `0x80000000` (файловий зсув `offset = vaddr - 0x80000000`)
- **Дизасемблер:** `arm-none-symbianelf-objdump.exe -D -b binary -m arm --adjust-vma=0x80000000`

## 2. Пошук штатної розкладки тактування E90

### 2.1. Аналіз пулів віртуальних адрес `0xc6008240` (CORE) та `0xc6008140` (MPU)

У нестисненому XIP виконано пошук літералів `40 82 00 c6` (`0xc6008240`) та `40 81 00 c6` (`0xc6008140`):

1. **`0xc6008240` (`CM_CLKSEL1_CORE`):** знайдено рівно 4 входження:
   - `0x80059e0c`: використовується 7 сеттерами `0x80059960`–`0x80059a94` у `power.dll` (налаштування бітових полів `L3`, `L4`, `DSS1`, `DSS2`, `VLYNQ`, `SSI`, `USB`). Кожен сеттер приймає аргумент у `r1` від викликача і виконує RMW через `0x8005f0e4`. Жодної повної константи туди не пишеться.
   - `0x800b76a4`: використовується очищенням біта DSS2 (`0x800b6cf8`) і читачем частоти (`0x800b7204`).
   - `0x800bdd24`: використовується очищенням біта DSS2 (`0x800bdb24`) і читанням поля [6:5] (`0x800bdc48`).
   - `0x800c307c`: використовується читанням (`0x800c281c`) і очищенням біта DSS2 (`0x800c2f54`).
2. **`0xc6008140` (`CM_CLKSEL_MPU`):** знайдено рівно 2 входження:
   - `0x80059e08`: сеттер `iMpuSetter` (`0x80059914`), валідує аргумент `r1` і пише його в регістр через `0x8005f0e4`.
   - `0x8005ebac`: функція `GetMpuClockFrequency` (`0x8005eab4`), виключно читає регістр для розрахунку частоти.

**Висновок для віртуального простору (`power.dll`):** Запис цілісної штатної розкладки у віртуальні регістри `0xc6008240` / `0xc6008140` **у резидентному XIP відсутній**.

### 2.2. Знахідка: апаратна init-послідовність тактування у Bootstrap (фізичні адреси)

У коді ранньої ініціалізації SoC (bootstrap, виконання без MMU з фізичної бази PRCM `0x48008000`, пул за адресою `0x80001e30`) **знайдено пряме програмування всіх регістрів тактування**:

Дизасемблування вікна `0x80001910`–`0x800019a8`:

```arm
80001910:	e59f0518 	ldr	r0, [pc, #1304]	; 0x80001e30 = 0x48008000 (PRCM physical base)
80001914:	e3a01001 	mov	r1, #1
80001918:	e5801500 	str	r1, [r0, #1280]	; CM_CLKEN_PLL (0x500) = 1 (bypass)
8000191c:	e3a01002 	mov	r1, #2
80001920:	e5801544 	str	r1, [r0, #1348]	; CM_CLKSEL2_PLL (0x544) = 2 (CORE_CLK_SRC = 2 -> CORE = DPLL * 2)
80001924:	e59f1524 	ldr	r1, [pc, #1316]	; 0x80001e50 = 0x08301044
80001928:	e5801240 	str	r1, [r0, #576]	; CM_CLKSEL1_CORE (0x240) = 0x08301044
8000192c:	e3a01002 	mov	r1, #2
80001930:	e5801140 	str	r1, [r0, #320]	; CM_CLKSEL_MPU (0x140) = 2
80001934:	e3a01002 	mov	r1, #2
80001938:	e5801340 	str	r1, [r0, #832]	; CM_CLKSEL_GFX (0x340) = 2
8000193c:	e59f1510 	ldr	r1, [pc, #1296]	; 0x80001e54 = 0x000023c3
80001940:	e5801840 	str	r1, [r0, #2112]	; CM_CLKSEL_DSP (0x840) = 0x000023c3
```

Літеральний пул bootstrap (`0x80001e50`–`0x80001e54`):
- `0x80001e50`: `44 10 30 08` -> `0x08301044` (`CM_CLKSEL1_CORE`)
- `0x80001e54`: `c3 23 00 00` -> `0x000023c3` (`CM_CLKSEL_DSP`)

#### Розбір значень регістрів, які записує Bootstrap:

1. **`CM_CLKSEL1_CORE` = `0x08301044`** (інструкція `0x80001928: str r1, [r0, #576]`):
   - `L3` [4:0] = `0x04` = **4** (шина памʼяті: `CORE / 4`)
   - `L4` [6:5] = `0x02` = **2** (периферійна шина: `L3 / 2`)
   - `DSS1` [12:8] = `0x10` = **16** (дисплей: `CORE / 16`) *(на RM-320 було 6; E90 має інші дисплеї 800x352 / 240x320)*
   - `DSS2` [13] = `0`
   - `VLYNQ` [19:15] = `0`
   - `SSI` [24:20] = `0x03` = **3** (модемний канал: `CORE / 3`)
   - `USB` [27:25] = `0x04` = **4**

2. **`CM_CLKSEL_MPU` = `0x00000002`** (інструкція `0x80001930: str r1, [r0, #320]`):
   - `MPU_DIV` [4:0] = **2** (`CORE / 2`)

3. **`CM_CLKSEL2_PLL` = `0x00000002`** (інструкція `0x80001920: str r1, [r0, #1348]`):
   - `CORE_CLK_SRC` [1:0] = **2** (`CORE = DPLL * 2`)

4. **Множник і дільник DPLL (`CM_CLKSEL1_PLL`)**:
   За адресами `0x80001840`–`0x800018ac` bootstrap вимірює тактову частоту опорного генератора (кварцу) апаратним 32-кГц таймером (`0x48028000`):
   - якщо лічильник > 500: опорна частота **19.2 МГц** (`sysSel = 0`);
   - якщо 390 < лічильник <= 500: опорна частота **13.0 МГц** (`sysSel = 2`);
   - якщо лічильник <= 390: опорна частота **12.0 МГц** (`sysSel = 3`).

   Далі за адресою `0x80001944`–`0x800019a4` обчислюється і записується множник DPLL:
   ```arm
   80001944:	e5907540 	ldr	r7, [r0, #1344]	; CM_CLKSEL1_PLL
   80001948:	e207250e 	and	r2, r7, #58720256 ; 0x3800000 (bits [25:23])
   8000194c:	e1a02ba2 	mov	r2, r2, lsr #23
   80001950:	e3a05003 	mov	r5, #3
   80001954:	e1550002 	cmp	r5, r2
   80001958:	0a000007 	beq	0x8000197c	; гілка 12 МГц
   8000195c:	e3a05002 	mov	r5, #2
   80001960:	e1550002 	cmp	r5, r2
   80001964:	0a000009 	beq	0x80001990	; гілка 13 МГц
   ; Гілка 19.2 МГц (стандарт для Nokia BB5 OMAP2420):
   80001968:	e3a01061 	mov	r1, #97	; 0x61 = 97 -> mult
   8000196c:	e3a02006 	mov	r2, #6	; 0x06 = 6  -> div (div + 1 = 7)
   80001970:	e1a01601 	mov	r1, r1, lsl #12
   80001974:	e0811402 	add	r1, r1, r2, lsl #8
   80001978:	ea000008 	b	0x800019a0
   ; Гілка 12 МГц:
   8000197c:	e3a01085 	mov	r1, #133 ; mult = 133, div = 5 (div+1 = 6) -> DPLL = 266.0 МГц
   ...
   ; Гілка 13 МГц:
   80001990:	e3a01029 	mov	r1, #41  ; mult = 41,  div = 1 (div+1 = 2) -> DPLL = 266.5 МГц
   ...
   800019a0:	e1877001 	orr	r7, r7, r1
   800019a4:	e5807540 	str	r7, [r0, #1344]	; CM_CLKSEL1_PLL (+0x540)
   ```

   **Для штатного кварцу 19.2 МГц:**
   - Поле `DPLL_MULT` [21:12] = **97** (`0x61`)
   - Поле `DPLL_DIV` [11:8] = **6** (`0x06`), дільник `div + 1` = **7**
   - Розрахункова частота DPLL на старті: `19.2 МГц * 97 / 7 =` **266.057 МГц** (базова частота 266 МГц).
   - Частота CORE: `266.057 * 2 =` **532.114 МГц**.
   - Частота MPU: `532.114 / 2 =` **266.057 МГц**.
   - Частота шини L3: `532.114 / 4 =` **133.028 МГц**.
   - Частота DSS1: `532.114 / 16 =` **33.257 МГц**.

### 2.3. Чи програмується в резидентному XIP перехід на 330 МГц (mult = 86)?

- **У нестисненому XIP `out/roms/e90.rom` вторинного переходу на 330 МГц не знайдено.**
  Вичерпний пошук по всьому бінарному файлу показав:
  * Значення `0x00056400` (`mult=86, div=4`, яке дає 330.24 МГц) присутнє лише як бітова маска константи в `0x800b76b4`.
  * Будь-які інші записи до `CM_CLKSEL1_PLL` (`offset 0x540`), крім `0x800018b0` та `0x800019a4` у bootstrap, **відсутні у всьому образі XIP**.
  * Віртуальні сеттери `power.dll` не містять зашитих констант і лише опрацьовують зовнішні виклики.
- **Висновок:** Якщо прошивка Nokia E90 згодом перемикає процесор на 330 МГц (або іншу цільову рампа-частоту), цей код міститься у **стисненій/пейджованій частині ROM (ROFS)**, якої в сирому XIP-образі немає.
